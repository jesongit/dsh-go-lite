# 远程主机

DSH 运行在电脑或服务器上，DSH Go 通过 SSH 或 DSH Remote 连接。对话、工作区、模型和插件属于那台主机；手机不安装或启动 DSH 运行环境。

## 首次使用与未选择主机

发送消息前先添加并选择远程主机。首次使用且没有主机、旧配置选中已移除的本机主机时，都从未选择开始。删除当前主机或退出它的 DSH Remote 账号后，也会回到未选择。App 不会替你选择另一台已保存或在线的主机。

开启**连接上次使用的主机**时，打开 App 会尝试重连上次明确选择且仍有效的远程主机；关闭后手动连接。主机离线或尚未信任时，需先解决连接问题，不会把对话转给其他主机。

旧本地主目录留在手机私有数据中，不会上传或删除。见 [升级与旧本地数据](04-legacy-data.md)。

## 切换主机

打开对话列表，点底部的主机名进入**切换主机**，选择远程主机。还没保存主机时点**连接电脑或服务器**，已有时点**管理远程主机**。点名称旁的图标查看连接详情、当前路径和支持时的延迟。

## 添加 SSH 主机

那台主机需要开启 SSH，并装好 DSH（`npm i -g @deepseek-ai/dsh`）。

1. 点**添加 SSH 主机**。
2. 填**主机**和**用户名**，**端口**默认 22，名称可留空。
3. 选**密码**或**私钥**。私钥可以**从文件导入**，有口令时填**私钥密码（可选）**；保存的凭据留在这台手机上。
4. **启动命令**默认 `dsh web`；用 nvm 安装时可能需要完整路径。**工作目录（可选）**设置新对话的默认目录。
5. 点**测试连接**。出现**信任这台主机？**时，先在主机核对指纹，一致才点**信任并连接**。
6. 点**保存**，再选中主机。

测试会启动远端 DSH，结束后继续运行。点**编辑**修改主机；**删除这台主机**只移除手机上的连接设置和凭据，远端 DSH 与对话保留。删的是当前主机时，之后没有主机被选中。

SSH 把远端 Web 服务转发到手机的 loopback 端口，为 HTTP API 和内嵌 DSH Web 提供通道；它不是手机本地 DSH 引擎。

## DSH Remote

1. 在主机的 DSH 中安装 Remote 插件并登录。
2. 在远程主机页选择相同登录方式和账号；如果只显示**在浏览器中登录**，点它继续。
3. 选在线主机，首次连接时与主机 Remote 插件核对身份指纹，一致才点**信任并连接**。

此登录用于 DSH Remote 连接。旧的本机 DeepSeek 登录已移除，模型凭据需要在所选主机配置。

加密连接默认自动尝试局域网/P2P、TURN，最后回落 Relay，相应路径需服务端和主机支持。点网络标签查看实际路径、连接耗时、可测延迟及回落原因；WebRTC 详情显示所选候选的 IPv4/IPv6、UDP/TCP，不暴露原始 IP。直连也不会解除下面的 API 限制。

<!-- nav: commonSettings,commonRemoteHost,remoteCompactHistory -->
`设置 › 远程主机 › 精简历史`

**精简历史**默认关闭。支持的主机在传输时摘要化历史工具参数和输出；正文、实时回复、审批和主机原始记录不变。修改后切换到其他主机再回来，或重启 App 生效；自动重连沿用原模式。旧主机仍发送完整历史，SSH 不受影响。

DSH Remote 一次只连接一台主机，切换会断开上一台。

## 当前功能限制

| 功能 | SSH | DSH Remote |
|---|---|---|
| 对话、工作区和审批 | 现有主机 API | 支持的主机 API |
| 文件附件 | 远端上传 API | 兼容主机协商后支持文件上传，旧主机仅图片 |
| 插件列表、市场与开关 | 可用 | 现有放行接口 |
| 插件安装/卸载 | 通过主机接口可用 | 当前传输未放行，请在主机执行命令 |
| 原生插件界面、桥接配置与素材 | 主机需安装兼容 dsh-go bridge | HTTP 桥接路由不可达 |
| 内嵌 DSH Web、插件 WebView | 通过 SSH 隧道可用 | 不可用，直连路径也一样 |
| DS Bot、对话日志 ZIP 导出 | 主机需提供相应 API | 当前传输不可用 |
| 技能及个人指令文件导入导出 | 不保证可用，部分旧路径依赖手机运行环境 | 不保证可用 |

文件上传限制和失败处理见 [对话](01-chat.md)。App 的分享与回放不同于主机日志 ZIP 导出。目前没有实现让远端 AI 操控这台手机的协议。
